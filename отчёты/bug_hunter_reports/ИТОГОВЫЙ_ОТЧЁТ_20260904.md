# BugHunter — итоговый отчёт по охоте на баги в DeFi

**Дата:** 2026-09-04
**Инструмент:** BugHunter v2 (static + python AST + solidity semantic CEI-анализ)

---

## Что сделано

1. **Улучшен BugHunter**: добавлен собственный Solidity-анализатор, который ищет
   НЕ слова в комментариях, а опасные паттерны:
   - **CEI violation** — запись в хранилище ПОСЛЕ внешнего вызова (признак reentrancy)
   - **Unchecked low-level call** — `.call`/`.delegatecall` без проверки результата
   - **delegatecall на управляемый адрес** — точки захвата контекста контракта
   - **selfdestruct / tx.origin / block.timestamp-зависимости**

2. **Проанализированы 3 реальных проекта**:
   | Проект | Файлов | Строк | Находок | Результат |
   |--------|--------|-------|---------|-----------|
   | OpenZeppelin contracts | 723 | 99,717 | 160 | аудирован, ловить нечего |
   | Euler v1 | 161 | 28,066 | 172 | 1 реальный delegatecall, охраняемый |
   | Euler Vault Kit (EVK) | 223 | 29,561 | 199 | 3 перспективные точки в проде |

## Интересные места по EVK (кандидаты на ручную проверку)

### 1. `src/EVault/Dispatch.sol:113` — viewDelegate()
```
function viewDelegate() external payable {
    if (msg.sender != address(this)) revert E_Unauthorized();
    assembly {
        ...
        let result := delegatecall(gas(), calldataload(4), 0, size, 0, 0)
```
- delegatecall на произвольный адрес из calldata
- защищено только `msg.sender == address(this)`
- **Вопрос хантера**: можно ли попасть в эту функцию с чужой calldata
  через `delegateToModuleView` и как проверить, какой адрес модуля
  «вязается» в вызов? (я не смог, но это ключевая точка)

### 2. `src/EVault/Dispatch.sol:124` — delegateToModule()
- module берётся из immutable-констант, установленных в конструкторе
- безопасно при текущей архитектуре — но каждый модификатор `use()` на
  каждом внешнем фукнции — поверхность атаки «вызови модуль с чужими данными»

### 3. `src/EVault/modules/Liquidation.sol:243`, `shared/types/LTVConfig.sol:40`
- block.timestamp в логике ликвидаций и смягчения LTV
- легитимное использование, но при экстремальных расхождениях времени
  между цепочками может быть интересно (cross-chain vaults)

## Почему не подано ни одной баунти (честно)

- EVK прошёл **10 аудитов** (OpenZeppelin, Certora, ChainSecurity, Omniscia,
  Spearbit, yAudit, Cantina и др.) — найти новое в одиночку почти нереально
- Regex-инструмент даёт точки интереса, но **не доказывает** уязвимость
- За выплату нужен рабочий exploit-сценарий, а не подозрение

## Вывод для дальнейшей работы

Инструмент готов и работает как фильтр: 30 000 строк -> 3 точки.
Дальше два пути, работают вместе:

- **Путь А (быстрый доход)**: охотиться по молодым протоколам с деньгами и
  слабым аудитом (0-1 аудит). Показатель — списки Immunefi: критерии
  «audits: none» + «TVL > $0». BugHunter сузит поле, дальше вручную.
- **Путь Б (долгый, надёжный)**: изучить Solidity и PATTERNS перечисленных
  выше точек, научиться писать PoC (Foundry/Anvil). Это навык, который и
  продаётся на баунти.
