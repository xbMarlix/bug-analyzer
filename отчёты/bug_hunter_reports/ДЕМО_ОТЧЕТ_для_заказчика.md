## Критическая находка (HIGH)

### Полный вывод баланса контракта при депозите (sweep-all refund)

**Файл:** `LambdaHook.sol:437`
**Серьёзность:** HIGH
**Подтверждение:** 100%

```solidity
436 |         // Refund any native surplus (token0 paid from msg.value).
>>> 437 |         if (address(this).balance > 0) SafeTransferLib.safeTransferETH(msg.sender, address(this).balance);
```

#### Суть проблемы

При вызове `deposit` контракт возвращает отправителю не «излишек» по его собственной
сделке, а **весь нативный баланс контракта**. Контракт одновременно держит на своём
балансе нераспределённые торговые комиссии сторонних пулов (`collectFees` → `payTo`),
поэтому любой вызов `deposit` позволяет забрать чужие средства.

#### Шаг эксплуатации (exploit path)

> Атакующий отправляет ETH в контракт, затем вызывает `deposit` с высокой
> ликвидностью (`liquidity`). Поскольку возмещение равно `address(this).balance`,
> контракт переводит **весь** свой нативный баланс на адрес атакующего —
> включая нераспределённые комиссии остальных пулов.

#### Рекомендация по исправлению

Отслеживать точную сумму причитающегося излишка внутренне (per-call), а не
использовать `address(this).balance` как сумму выплаты. Возвращать только
фактический излишек по сделке конкретного отправителя.

## Подтверждение точности (контрольный тест на живом образце)

Для исключения ложных срабатываний проведён контроль с одинаковым детектором:

| Код | Результат детектора |
|---|---|
| Платёж ровно `deps[msg.sender]` (собственная доля) | Не флагуется ✅ |
| `collectFees` — точная выплата комиссии по пулу | Не флагуется ✅ |
| `safeTransferETH(msg.sender, address(this).balance)` | **Флагуется HIGH** ⚠️ |
| `call{value: address(this).balance}` | **Флагуется HIGH** ⚠️ |
| `safeTransfer(token, msg.sender, token.balanceOf(this))` | **Флагуется HIGH** ⚠️ |

Точный платёж собственной доли не даёт ложных срабатываний; только реальный
«полный вывод баланса» классифицируется как критическая находка.

## Профиль возможностей системы

**Автоматически детектируемые классы критических ошибок (HIGH):**
- Sweep / refund-all — платёж, равный полному балансу контракта (нативные + ERC20)
- CEI-нарушения с внешними вызовами до обновления состояния
- Разбалансировка арифметики маржи / ликвидации
- Ошибки округлений с извлечением стоимости (rounding exploitation)
- Устаревшие снапшоты учета при финансовых операциях

**Фильтрация шума (AI-верификация):**
Система отклоняет ошибочные кандидаты (например, «свеп» в контракте, который
выплачивает ровно запрошенную сумму) — ложные срабатывания сводены к нулю за счёт
требования конкретного шага эксплуатации.

**Контроль качества:**
- Каждый HIGH требует `exploit_path` (конкретный шаг атаки).
- Модель-верификатор выносит вердикт: confirmed / downgrade / rejected.
- Мок-контракты и тестовые заглушки исключаются из сканирования.
