## Accounting (2)

### [!!] Full-Balance Sweep in Payout
- **File:** `LambdaHook.sol:437`
- **Severity:** HIGH
**Problem:** A payout path sends the full contract balance instead of the exact amount owed. If the contract holds other users' funds or uncollected fees, any caller triggers this path and drains everything parked in the contract. This is a confirmed High/Critical class in competitive audits (refund-all / sweep-all).
EXPLOIT: An attacker can call the `deposit` function with a large `liquidity` value and a small `amount0Max` and `amount1Max` to trigger the payout path. This will cause the contract to send the full contract balance to the caller, draining all funds.
**Fix:** Pay the caller's exact tracked entitlement; never use address(this).balance or balanceOf(address(this)) as the payout amount.

### [!!] Potential rounding error in funding distribution
- **File:** `Funding.sol:130`
- **Severity:** HIGH
**Problem:** The function `claim` uses floor-rounding in the per-share accumulator, which can lead to a few wei being left unclaimed over time.
EXPLOIT: If the per-share accumulator is not perfectly aligned with the actual funding deposited, the last claimant can be left short by a few wei.
IMPACT: The last claimant might receive less funding than they are owed, leading to a small loss.
**Fix:** Ensure that the per-share accumulator is perfectly aligned with the actual funding deposited to avoid rounding errors.
